Actúa como agente de operación para GanaConMerito.

Objetivo:
Actualizar el VPS con la última versión real de `master` después del merge más reciente en GitHub, verificando la triple coincidencia:

1. Carpeta de producto: `~/.openclaw/product`
2. Carpeta deploy: `/opt/gcm/app`
3. Runtime Docker: contenedor `gcm-app`

Repositorio:
https://github.com/ProfeMarlonMDE/GanaConMerito

Entorno público:
https://cnsc.profemarlon.com

IMPORTANTE:
No uses el hash de la rama ni el hash del PR antes del merge. Después de aceptar el PR en GitHub, debes obtener el hash final real de `origin/master`.

El hash final puede cambiar respecto al hash que aparece en el PR porque GitHub puede crear un merge commit. Por eso, antes de desplegar, calcula el hash desde `origin/master`.

Tareas:

1. Conectarte al VPS:

ssh ganaconmerito

2. En el VPS, obtener el último hash real de `master`:

cd ~/.openclaw/product
git fetch origin
git checkout master
git reset --hard origin/master
FINAL_COMMIT=$(git rev-parse HEAD)
FINAL_SHORT=$(git rev-parse --short HEAD)

echo "FINAL_COMMIT=$FINAL_COMMIT"
echo "FINAL_SHORT=$FINAL_SHORT"

3. Actualizar carpeta de producto:

cd ~/.openclaw/product
git fetch origin
git checkout master
git reset --hard "$FINAL_COMMIT"

SOURCE_HEAD=$(git rev-parse HEAD)
echo "SOURCE_HEAD=$SOURCE_HEAD"

4. Actualizar carpeta deploy:

sudo git -C /opt/gcm/app fetch origin
sudo git -C /opt/gcm/app checkout master
sudo git -C /opt/gcm/app reset --hard "$FINAL_COMMIT"

DEPLOY_HEAD=$(sudo git -C /opt/gcm/app rev-parse HEAD)
echo "DEPLOY_HEAD=$DEPLOY_HEAD"

5. Verificar coincidencia source/deploy:

test "$SOURCE_HEAD" = "$DEPLOY_HEAD"
echo "SOURCE_DEPLOY_MATCH=OK"

6. Verificar si existe migración nueva de Supabase:

ls -la /opt/gcm/app/supabase/migrations | tail -n 20

Debe existir, si el PR #9 ya está mergeado:

supabase/migrations/0007_tutor_turn_traces.sql

Si no existe, detenerse y reportar que el PR #9 no está en master.

7. Aplicar o verificar migraciones Supabase.

IMPORTANTE:
El PR #9 agrega la tabla `tutor_turn_traces`. Sin esa migración, la app puede funcionar, pero la persistencia de trazas del Tutor GCM no quedará activa.

Si el proyecto tiene flujo configurado de Supabase CLI en el VPS, ejecutar el comando institucional existente para aplicar migraciones.

Si NO está configurado el flujo de migraciones en VPS, NO inventes comandos inseguros. Reporta como pendiente:

"Pendiente aplicar migración 0007_tutor_turn_traces.sql en Supabase."

No declares activa la persistencia de trazas hasta confirmar que la tabla existe.

8. Reconstruir Docker insistiendo en el commit correcto.

Usar el short hash del commit final real de `master`, no el hash de la rama ni el hash del PR.

cd /opt/gcm

APP_COMMIT=$(sudo git -C /opt/gcm/app rev-parse --short HEAD)
APP_BUILD_TIME=$(date -u +%Y-%m-%dT%H:%M:%SZ)

echo "Building Docker with APP_COMMIT=$APP_COMMIT"
echo "Building Docker with APP_BUILD_TIME=$APP_BUILD_TIME"

sudo docker compose -f docker-compose.yml build \
  --build-arg APP_COMMIT="$APP_COMMIT" \
  --build-arg APP_BUILD_TIME="$APP_BUILD_TIME" \
  gcm-app

sudo docker compose -f docker-compose.yml up -d gcm-app

9. Verificar Docker:

sudo docker ps | grep gcm-app
sudo docker logs --tail 50 gcm-app

Criterio PASS:
- `~/.openclaw/product` está en el hash final real de `master`.
- `/opt/gcm/app` está en el mismo hash.
- Docker fue reconstruido con ese short hash.
- `/login` muestra ese short hash.
- `gcm-app` está arriba.
- No hay errores críticos en logs.

Criterio WARN:
- App está arriba y commit coincide, pero la migración 0007 no pudo verificarse o aplicarse.

Criterio FAIL:
- Source/deploy no coinciden.
- Docker no levanta.
- Runtime muestra otro commit.
- App pública no responde.
