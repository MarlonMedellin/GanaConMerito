Quiero ejecutar el Sprint 37.1 de GanaConMerito.

Nombre del sprint:
Sprint 37.1 — Runtime Parity & Operational Verification

Trabaja como PM-Gauss y respeta disciplina estricta de producto, release, documentación y anti-drift.

## Contexto

Sprint 37 quedó cerrado solo a nivel repo/governance, pero NO quedó cerrado a nivel runtime operacional.

El Sprint 38 ya está reservado/ocupado, por eso este cierre se manejará como Sprint 37.1.

## Objetivo

Cerrar la deuda operacional pendiente de Sprint 37 validando que:

~/.openclaw/product
→ /opt/gcm/app
→ Docker runtime
→ https://cnsc.profemarlon.com

representan exactamente el mismo estado funcional y documental.

## Reglas obligatorias

1. Trabaja primero en la fuente canónica:
   ~/.openclaw/product

2. No corrijas primero en deploy.

3. No hagas hotfix directo en:
   /opt/gcm/app

4. Si algo falla, corrige primero en:
   ~/.openclaw/product

5. Luego alinea:
   /opt/gcm/app

6. Después reconstruye/reinicia/verifica Docker.

7. No declares Sprint 37.1 cerrado si no validaste runtime real.

## Secuencia obligatoria

### 1. Verificar fuente canónica

Entra a:

cd ~/.openclaw/product

Ejecuta:

git status
git branch
git log --oneline -5
git fetch origin
git checkout master
git pull origin master

Confirma el HEAD actual y que contiene los cambios documentales del Sprint 37.

### 2. Validar repo local

Ejecuta:

npm run lint
npm run build
npm run test:recent-sprints
npm run test:unit
npm run test:tutor

Si algo falla, corrige en fuente canónica, documenta el fallo y vuelve a correr pruebas.

### 3. Alinear deploy tree

Entra a:

cd /opt/gcm/app

Ejecuta:

git status
git log --oneline -5
git fetch origin
git checkout master
git pull origin master

Confirma que el HEAD de /opt/gcm/app coincide con el HEAD de ~/.openclaw/product.

### 4. Verificar entorno persistente

Verifica que exista:

/opt/gcm/env/gcm-app.env

No imprimas secretos.

Solo confirma:
- existe
- es legible por el proceso esperado
- contiene las variables necesarias para runtime y QA

### 5. Verificar Docker

Ejecuta desde /opt/gcm/app:

docker ps
docker compose ps

Luego, si aplica:

docker compose build
docker compose up -d

Revisa logs:

docker compose logs --tail=200

Confirma:
- contenedor healthy o estable
- puerto esperado activo
- no hay errores críticos de Supabase/env/build

### 6. Validar metadata pública

Verifica:

https://cnsc.profemarlon.com/login

Confirma:
- commit hash visible o detectable
- buildTime visible o detectable
- runtime corresponde al HEAD desplegado
- no hay mismatch entre repo, deploy y runtime

Puedes usar curl si el entorno lo permite:

curl -sS -D - https://cnsc.profemarlon.com/login -o /tmp/gcm_login.html

No declares PASS si la red bloquea la validación.

### 7. Ejecutar QA runtime

Desde entorno con acceso real y variables válidas:

QA_BASE_URL=http://127.0.0.1:3000 REQUIRE_RUNTIME_METADATA=1 npm run qa:runtime:smoke

QA_BASE_URL=http://127.0.0.1:3000 npm run qa:smoke:postdeploy

QA_BASE_URL=https://cnsc.profemarlon.com npm run qa:e2e:api

QA_BASE_URL=https://cnsc.profemarlon.com npm run qa:e2e:ui

Reporta cada resultado por separado.

### 8. Validar Tutor GCM en runtime

Verifica manual o automáticamente que:

Antes de responder:
- no revela la clave
- no entrega la respuesta exacta
- solo ofrece hint seguro si aplica

Después de responder:
- puede explicar la clave
- puede justificar distractores
- puede explicar procedimiento

Nunca debe:
- alterar scoring
- alterar progreso
- cerrar sesión
- seleccionar ítems
- invadir decisiones críticas del sistema
